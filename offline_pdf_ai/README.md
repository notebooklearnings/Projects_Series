# Offline PDF AI: search your PDFs with AI, no internet

Code for the Notebook Learnings video **"I Built an AI That Searches My PDFs, Completely Offline"**
▶ Video: https://youtu.be/futkMux1UVU

Ask questions about a folder of PDFs. You get:
- an answer in plain English, with a citation number after every fact
- the **file name and page number** for each source
- the **exact passage highlighted** on an image of the page (`show`)
- **"I couldn't find that in your documents."** when the answer isn't there, instead of a made-up answer

One Python file (`pdfai.py`, ~215 lines). No LangChain, no vector database, no API key. Runs on an ordinary laptop without a GPU.

## How it works
```
INDEX (once):  PDFs -> pages -> ~900-char passages -> nomic-embed-text -> vectors.npy + chunks.json
ASK:           question -> same embedding model -> cosine similarity vs every passage
               -> top 4 above MIN_SCORE -> llama3.2:3b with numbered sources -> answer + [file, page]
```
Two "not found" guards:
1. **Similarity threshold**: if no passage scores at least `MIN_SCORE`, the language model is never called.
2. **Prompt rule**: the model must reply with the exact not-found sentence when the sources don't contain the answer.

## Setup
1. Install **Ollama**: https://ollama.com
2. Download two models (the only step that needs internet, about 2.3 GB):
   ```
   ollama pull nomic-embed-text
   ollama pull llama3.2:3b
   ```
3. Python environment:
   ```
   python -m venv .venv
   .venv\Scripts\activate            # Mac/Linux: source .venv/bin/activate
   pip install -r requirements.txt
   ```

## Use
```
python pdfai.py index sample_pdfs
python pdfai.py ask "How wide must the fire escape stairs be?" --show
python pdfai.py chat                 # type 'show 1' to open source [1], 'quit' to exit
```
Point `index` at your own folder (subfolders are included). Re-run `index` when your documents change.

## Calibrate MIN_SCORE (do this once)
Every embedding model scores on its own scale. Ask 5 questions you know are answered and 5 you know are not.
Note the `match` scores (refusals print `best match only ...`). Set `MIN_SCORE` in `pdfai.py` in the gap between the two groups.

## Settings (top of pdfai.py)
| Setting | Default | Meaning |
|---|---|---|
| `EMBED_MODEL` | nomic-embed-text | turns text into vectors |
| `CHAT_MODEL` | llama3.2:3b | writes the answers; try a bigger model if you have the RAM |
| `CHUNK_SIZE` / `OVERLAP` | 900 / 150 | passage length and shared characters, in characters |
| `TOP_K` | 4 | passages given to the model |
| `MIN_SCORE` | 0.55 | similarity threshold for "not found"; **calibrate it** |

## Limits
- **Scanned PDFs** have no text layer, so run OCR first (e.g. `ocrmypdf`).
- **Tables and drawings** lose their structure as text, so check the page with `show`.
- **Answers spread across many pages**: raise `TOP_K` and `num_ctx` (slower).

## Sample data
`sample_pdfs/` contains 10 **fictional** project documents ("Lakeview Residences", 87 pages) generated by `make_sample_pdfs.py`.
Try: *"How wide must the fire escape stairs be?"* (answer: Fire Safety Report, page 9) and *"What is the visitor parking fee per hour?"* (not in the documents).
